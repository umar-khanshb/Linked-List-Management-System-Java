+----------------------------+----------------------------------+----------------------------------+
| Feature                    | Singly Linked List               | Doubly Linked List               |
+----------------------------+----------------------------------+----------------------------------+
| Node structure             | data + next                      | data + prev + next               |
| References per node        | 1                                | 2                                |
| Forward traversal          | Yes                              | Yes                              |
| Backward traversal         | No (needs extra work)            | Yes (using prev)                 |
| Memory overhead            | Lower (1 reference/node)         | Higher (2 references/node)       |
| Insert at beginning        | O(1)                             | O(1)                             |
| Insert at end              | O(n) (no tail in this project)   | O(1) (tail maintained)           |
| Delete at beginning        | O(1)                             | O(1)                             |
| Delete at end              | O(n) (find 2nd-last node)        | O(1) (tail.prev is known)        |
| Delete a known node        | O(n) (needs predecessor)         | O(1) (has prev and next)         |
| Search by value            | O(n)                             | O(n)                             |
| Reverse                    | O(n) (re-point next)             | O(n) (swap prev and next)        |
| Typical use cases          | Stacks, simple queues,           | Browser history, undo/redo,      |
|                            | adjacency lists                  | playlists, LRU caches            |
+----------------------------+----------------------------------+----------------------------------+

Key points:
1. A singly linked list stores fewer references per node, so it uses less memory.
2. A doubly linked list can be traversed in both directions, but every node
   stores an extra reference and every insert or delete must update more links.
3. The complexities above depend on the implementation. Here the singly list has
   only a head reference, while the doubly list keeps head and tail.
4. A linked list is not always faster than an array. Arrays give O(1) access by
   index and are cache-friendly; linked lists are useful when frequent insertion
   and deletion happen at known nodes and index access is not needed.
